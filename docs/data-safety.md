# 数据保护与恢复

## 哪些目录需要备份

1. 当前存档目录：所有 .md、tags.json 和 .assets/。
2. ~/QuickMD/：.float-buffer/、.recovery/。如果存在旧版本的 .trash/，也保留其备份。
3. 系统配置目录的 QuickMD/settings.json。

主题、置顶和浮窗标题是 WebView 本地状态，不属于正文文件；普通文件备份不会自动还原这些 UI 偏好。开发时设置 QUICKMD_DATA_DIR 可以把上述应用数据和配置统一隔离到一个可丢弃目录。

## 恢复

- 删除会直接移入 Windows 系统回收站；需要时在系统回收站中还原，重新启动应用后档案列表会重新读取。系统还原的是 Markdown 文件，独立标签和置顶记录需要重新添加；图片副本保留在 .assets/。
- 应用不再创建或维护独立回收站。旧版本 .trash/ 内容不自动迁移或清理：其中 content.md 是正文，metadata.json 首项是原文件名、第二项是旧标签。需要手动找回时另存到档案目录，重名先改名，不覆盖已有文档。
- 回收站操作失败不会切换为空白会话；保存失败会阻止删除。网络及特殊路径不支持当前系统回收站调用时明确报错，没有永久删除回退。
- 正文上一版位于 .recovery/notes/，草稿上一版位于 .recovery/buffer.md。需要人工恢复时先退出应用，另存当前版本，再比较、复制需要的正文；不要盲目覆盖唯一副本。
- 配置或标签损坏时应用返回错误，不把它们悄悄当成空数据。先保留损坏文件，再从自己的备份恢复。
- 目录更改使用复制模型，旧目录不会自动删除。确认新目录完整可用之后，再由你决定如何处理旧副本。

## 能保证的边界

正常保存采用原子替换，创建不覆盖已有文件；关闭和转移等待保存结果。上一版用于恢复，不是完整历史版本库。断电、磁盘硬件损坏、外部程序同时覆写和强制终止前尚未保存的输入，仍需要独立备份与环境验证。

首次初始化提供 SOUL.md 与 Markdown 语法指南.md，已有同名文档不覆盖；完成标记 .initial-documents-v1.json 也应随数据根备份。初始化后用户删除的初始文档不会在重启时重建。指南是普通可编辑文档，底部独立教程入口移除。插入图片复制原图，不写回原图。浏览器预览只使用内存样例，不访问个人文件。
