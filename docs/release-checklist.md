# 候选包与公开发布

## 本地整备

1. npm ci → npm run check → npm test → npm run test:rust。
2. npm audit；cargo audit --file src-tauri/Cargo.lock。修复或明确记录当前公告与维护告警。
3. npm run tauri build；计算两个安装包的大小、签名与 SHA-256。
4. npm run notices 生成依赖声明；从核对过的公开文件集合生成源码归档，包含代码、双语模板、构建脚本、文档、图标与 README 素材。
5. 使用隔离目录做原生检查，再在干净 Windows 账户做安装/升级/卸载、高 DPI 与热键冲突矩阵。

自动检查、前端构建和本机启动各自提供不同的证据，不能替代干净环境安装验收。原生开发与测试应先设置绝对路径 `QUICKMD_DATA_DIR`，避免访问个人便利贴。

## 公开前

- 指定 GitHub 仓库，核对源码快照和候选包。保留原本 Git 历史和备份；首次快照不会附带个人 refs、审查临时文件或用户数据。
- 检查工作目录及拟公开历史中是否有凭据、个人记录、运行数据和临时文件；作者配置中的公开联系方式和支持图片需由维护者确认。
- 内置欢迎文档与 Markdown 指南的中文事实修订及完整英文对译已于 2026-10-11 经作者确认并应用；首次启动双语播种已通过隔离原生检查，维护者于同日确认完成本机原生验收。其他 Windows 环境及安装生命周期矩阵继续按实际执行结果记录。
- 检查 Release 说明、签名状态、体积和哈希，启用私密漏洞报告，确保 README 下载说明匹配真实入口。
- 运行 GitHub CI 并保存结果；本地编译不代表远程 CI 已运行。
- 为验收后的代码创建 release tag，再公开源码和安装包；不要把未完成的人工矩阵标成通过。

数字签名需要维护者自己的证书。未签名候选包可供本地审阅，其状态必须如实注明。源码 MIT 与第三方许可证原文分别保留。
